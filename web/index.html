01 / The language

Your problem already has a language.

Most programming languages make you translate that language into their grammar. DynLex makes grammar programmable.

01

Define a pattern

function total price for quantity items:
    execute:
        return price * quantity

Literal words form the readable structure. Used words become typed parameters through inference.

same program
02

Use the language you made

set subtotal to total 24.95 for 3 items
print subtotal as line

No parser plug-in. No preprocessor. The pattern participates in normal matching, overload resolution, and type inference.

Aa

Syntax that says why

Shape APIs around the vocabulary of the work, from business rules to graphics.

T?

Inferred, not untyped

DynLex resolves static types and overloads without making every call read like a declaration.

{ }

The library is the language

Core behavior stays small. Reusable language behavior lives in readable DynLex patterns.

02 / One compiler, real targets

Readable at the top.
Serious underneath.

DynLex is a C++23 compiler built on LLVM 20. It resolves pattern calls, infers types, and branches into target-specific code generation only after the program is understood.

04 / Project status

Early. Working.
Built in public.

DynLex is at version 0.0.1: usable enough to explore, young enough that compiler maturity, the standard library, diagnostics, and documentation are still moving quickly.

Available today

  • Standard library in DynLex
  • Web compiler and Monaco IDE
